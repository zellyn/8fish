# ===========================================================================
# BREADTH SECTION
#
# Everything above this line is a MAIN LINE: a sound variation we are happy
# to reach from either side, drilled 10-16 plies deep. Everything below is
# BREADTH: short lines whose only job is to have a sane, developing answer
# ready for a move a real opponent might actually play, so that the engine
# does not fall out of book on move 1 and does not have to find its opening
# moves by searching four plies deep on an Apple IIe.
#
# The "/b" and "/w" suffixes on the ECO code are what make this safe. A bare
# ECO code compiles EVERY move of the line into the book, so the engine will
# both play the line and answer it. "/b" compiles only Black's moves and
# "/w" only White's. That is how we can answer 1.g4 without ever playing it,
# and how we can punish 1...h5 without ever playing it. Our own first-move
# repertoire therefore stays exactly what it was: e4, d4, c4, Nf3.
#
# Many breadth lines deliberately TRANSPOSE into a line declared earlier in
# this file. A transposition is the cheapest breadth there is: it costs only
# the entries up to the join, and then inherits that line's whole remaining
# depth for free, because the book is keyed on the POSITION, not the move
# order. `go test ./internal/book -run TestBookTranspositions -v` prints
# exactly which lines do it, recomputed from this file — do not try to keep
# a hand-written list here in sync.
# ===========================================================================
